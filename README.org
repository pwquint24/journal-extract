* Journal Extract

An Emacs Lisp utility that reads a single org-mode "journal" file and moves its tagged entries out into one file per tag.

Each date entry in the journal is examined for tags. For every tag found, the
entry's content is appended to a file named after that tag (for example
=MytopicA.org=), so related notes naturally accumulate into topic files.

Vibe coded with DeepSeek

** How it works

Given a journal like this:

#+BEGIN_SRC org
* Journal

** 2026-09-18 Fri 16:50

*** Some more text with something else           :MyTopicA:
And in this case, we can add some notes as well ...

**** SubHeading

**** Another SubHeading
#+END_SRC

=journal-extract= produces an =MyTopicA.org=:

#+BEGIN_SRC org
* MyTopicA

** Some more text with something else
And in this case, we can add some notes as well ...

*** SubHeading

*** Another SubHeading
#+END_SRC

Notice what happened:

- The file was *created* with a top-level heading named after the tag
  (=* MyTopicA=).
- The date heading (=** 2026-09-18 Fri 16:50=) was *not* copied.
- Every heading was *outdented one level* (because the =**= date heading was
  removed): =***= -> =**=, =****= -> =***=.
- The =:MyTopicA:= tag was *stripped* from the moved content, since the file's
  own top heading already tells you the category.

Back in the source journal, the processed entry is marked so it won't be
moved again:

#+BEGIN_SRC org
** 2026-09-18 Fri 16:50 :copied:
#+END_SRC

** Requirements

- GNU Emacs (any reasonably recent version; tested with Emacs 31.1).
- Org mode (bundled with Emacs).

** Installation

Only =journal-extract.el= is needed to install and use the package. The
=test/= directory is for development only and is not installed.

*** Manual

Load the file into Emacs:

#+BEGIN_SRC elisp
(load-file "/path/to/journal-extract.el")
#+END_SRC

You can also add it to your init file:

#+BEGIN_SRC elisp
(add-to-list 'load-path "/path/to/journal-extract/")
(require 'journal-extract)
#+END_SRC

*** Doom Emacs

In your =packages.el= (usually =~/.config/doom/packages.el= or
=~/.doom.d/packages.el=), declare the package with a =:recipe= pointing at the
Git repository:

#+BEGIN_SRC elisp
;;; ~/.config/doom/packages.el
(package! journal-extract
  :recipe (:host github
            :repo "pwquint24/journal-extract"))
#+END_SRC

Then run:

#+BEGIN_SRC sh
doom sync
#+END_SRC

After syncing, use it in your config:

#+BEGIN_SRC elisp
(use-package! journal-extract
     :config
     (setq journal-extract-input-file "~/notes/journals.org")
     (setq journal-extract-target-directory "~/notes/topics/"))#+END_SRC


** Usage

*** Interactively

Run =M-x journal-extract RET=. If you haven't set the input file and target
directory (see below), it will prompt for them.

*** From Lisp

#+BEGIN_SRC elisp
(journal-extract "/path/to/journals.org" "/path/to/output-directory/")
#+END_SRC

Both arguments are optional and can be omitted if you use the configuration
variables instead.

** Configuration

All options are =defcustom=s, so you can set them with =M-x customize-group RET
journal-extract RET=, or in your init file.

*** =journal-extract-input-file=

Default input journal file. When =nil= (the default), =journal-extract=
prompts interactively, or you must pass the file as an argument.

#+BEGIN_SRC elisp
(setq journal-extract-input-file "~/notes/journals.org")
#+END_SRC

*** =journal-extract-target-directory=

Directory that receives the per-tag files. When =nil= (the default), files are
created next to the input file.

#+BEGIN_SRC elisp
(setq journal-extract-target-directory "~/notes/topics/")
#+END_SRC

*** =journal-extract-entry-level=

The heading level at which date entries live. Defaults to =2=.

#+BEGIN_SRC elisp
(setq journal-extract-entry-level 2)
#+END_SRC

*** =journal-extract-ignored-tags=

A list of tags to ignore. Two effects:

1. A date entry that already carries one of these tags is *skipped*.
2. These tags are *never exported* to their own file.

Defaults to =("copied")=, which is the marker =journal-extract= itself adds
after an entry has been processed. Add your own tags here if needed:

#+BEGIN_SRC elisp
(setq journal-extract-ignored-tags '("copied" "private"))
#+END_SRC

*** =journal-extract-tag-file-map=

An alist that renames tags to output file names, or sends several tags to one
file. Each entry is =(TAG . FILE-NAME)=. For example, both =:ArtHist:= and
=:art-history:= can share =ArtHistory.org=:

#+BEGIN_SRC elisp
(setq journal-extract-tag-file-map
      '(("ArtHist" . "ArtHistory")
        ("art-history" . "ArtHistory")))
#+END_SRC

Tags not present in the alist keep their own file name.

*** =journal-extract-preserve-date=

When =t=, each exported heading that sits directly under the date entry gets
a =:DATE:= property drawer holding the entry's full date header (for example
=2026-09-18 Fri 16:50=). This keeps some provenance in the topic files.
Defaults to =nil= (date headers are dropped).

#+BEGIN_SRC elisp
(setq journal-extract-preserve-date t)
#+END_SRC

Direct body text with no heading is exported unchanged and does not receive
the date property.

*** =journal-extract-dry-run=

When =t=, =journal-extract= performs a dry run: it reports which entries would
be exported, to which files, and which entries are untagged, but it writes
nothing and marks nothing. Defaults to =nil=.

#+BEGIN_SRC elisp
(setq journal-extract-dry-run t)
#+END_SRC

You can also run a one-off dry run interactively with =M-x
journal-extract-dry-run=.

** Input file format

- The journal should have one top-level heading (for example =* Journal=). This is left untouched.

- Date entries are the headings at =journal-extract-entry-level= (level 2 by default) whose title *starts with a digit*, e.g. =** 2026-09-18 Fri 16:50=.

- Content (notes) lives beneath each date entry at deeper levels. Tags are placed on any of these content headings:

#+BEGIN_SRC org
* Journal
** 2026-09-18 Fri 16:50
*** A note about this :MyTopicA:
**** A sub-point
#+END_SRC

** Behaviour details

- *Tag collection.* All tags in the entry's subtree are collected — from the
  date heading itself and all descendant headings and items — excluding the
  tags in =journal-extract-ignored-tags=.
- *Multiple tags.* If an entry has more than one tag, the whole block is
  copied to /each/ tag's file.
- *Order.* Within each tag file, entries keep their original document order.
- *Idempotency.* Processed entries are tagged =:copied:= and skipped on later
  runs, so re-running the command is safe and makes no changes.
- *Untagged entries.* A date entry with no exportable tags is left in place,
  is not marked =:copied:=, and is reported with a warning, so you can tag it
  later and run the command again.

** Example session

#+BEGIN_SRC elisp
;; One-time setup.
(add-to-list 'load-path "~/journal-extract/")
(require 'journal-extract)
(setq journal-extract-input-file "~/notes/journals.org")
(setq journal-extract-target-directory "~/notes/topics/")

;; Run it.
(journal-extract)
#+END_SRC

After running, =~/notes/topics/= will contain one org file per tag (created
as needed), and processed entries in =journals.org= will be marked =:copied:=.

** Backup & cleanup

Once entries have been marked =:copied:=, you can archive them out of your
journal to keep the journal itself lean.

*** =journal-extract-remove-copied=

Removes every =:copied:= date entry (including its contents) from the input
file. This is destructive, so it is normally used through
=journal-extract-archive-copied= instead.

#+BEGIN_SRC elisp
(journal-extract-remove-copied "/path/to/journals.org")
#+END_SRC

*** =journal-extract-archive-copied=

First copies every =:copied:= date entry -- including its date header -- into
a backup file, then removes them from the journal. The backup file keeps the
journal's top-level heading (for example =* Journal=) and appends new entries
on later runs.

The backup name is derived by inserting =-backup= before the extension:
=journals.org= becomes =journals-backup.org=.

#+BEGIN_SRC elisp
(journal-extract-archive-copied "/path/to/journals.org")
#+END_SRC

You can also pass an explicit backup file as the second argument:

#+BEGIN_SRC elisp
(journal-extract-archive-copied "/path/to/journals.org"
                                "/path/to/archive.org")
#+END_SRC

*** =journal-extract-prune-backup=

Removes date entries older than a given number of weeks from a backup file.
This lets you keep only recent backups, or clean an archive periodically.
Entries whose heading does not start with a parseable =YYYY-MM-DD= date are
left untouched.

#+BEGIN_SRC elisp
;; Remove backup entries older than 52 weeks.
(journal-extract-prune-backup 52 "/path/to/journals-backup.org")
#+END_SRC

The backup file argument is optional and defaults to the derived =-backup=
file for =journal-extract-input-file=.

All three commands are also available interactively (=M-x=) and reuse
=journal-extract-input-file= when no file argument is given.

** Testing

The test suite uses ERT (Emacs Lisp Regression Testing) and lives in the
=test/= directory, together with a fake =test-data/journals.org= fixture.

Run it from the =journal-extract/= directory:

#+BEGIN_SRC sh
emacs --batch -l test/journal-extract-tests.el -f ert-run-tests-batch-and-exit
#+END_SRC

The tests copy the fixture to a temporary directory, so your real journal
file is never touched.
